# Partner webhooks (operationStatusHook)

RaaS sends HTTP notifications to the URLs configured in the tenant (`operationStatusHook`).
The same signature mechanism is used for all events sent to those URLs.

## Request

- **Method:** `POST`
- **Content-Type:** `application/json`
- **Body:** Event JSON payload (see payload details by event type).

## Headers sent by RaaS

| Header              | Description |
|---------------------|-------------|
| `x-raas-signature`  | **Required.** HMAC signature of the request body so the partner can verify the request comes from RaaS. See [Signature verification](#signature-verification). |
| `x-raas-op-country` | Tenant country code (for example, `MX`). Optional context for the receiver. |

## Signature verification

The partner must verify the `x-raas-signature` header using the raw request body and the tenant `sharedSecret`.

### Algorithm

```text
signature = Base64( HMAC-SHA256( rawRequestBody, sharedSecret ) )
```

- **rawRequestBody:** raw request body (UTF-8 string), before parsing JSON.
- **sharedSecret:** shared secret configured for the tenant.
- **HMAC-SHA256:** RFC 2104 standard.
- **Base64:** standard encoding of the HMAC output.

### Example (Node.js)

```js
const crypto = require('crypto');

function verifyWebhookSignature(rawBody, signatureHeader, sharedSecret) {
  const expected = crypto
    .createHmac('sha256', sharedSecret)
    .update(rawBody, 'utf8')
    .digest('base64');

  return crypto.timingSafeEqual(
    Buffer.from(signatureHeader, 'base64'),
    Buffer.from(expected, 'base64')
  );
}
```

## request-money-full event

### `request_money_full_outcome`

Sent when the `request-money-full` flow finishes (success or failure). The partner endpoint must be idempotent by `correlationId`.

Main fields:

- `eventType`: always `"request_money_full_outcome"`.
- `correlationId`: correlation ID sent in the POST request.
- `status`: `"completed"` or `"failed"`.
- `date`: ISO 8601 timestamp.
- `errorCode`, `reason`, `phase`: only when `status === "failed"`.

## Endpoint error codes

Error responses from `POST /user/operations/request-money-full` use this format:

```json
{ "reason": "string", "code": "string" }
```

The `code` field is stable and should be used for integration logic.
